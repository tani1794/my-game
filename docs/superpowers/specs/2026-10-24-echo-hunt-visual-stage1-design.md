# OBLIVION ARENA 第1段階：ビジュアル再現 設計書

- 作成日：2026-10-24
- 状態：レビュー待ち

## 1. 目的

コンセプト画像（三人称視点で結晶獣と対峙する場面）の**雰囲気と画面構成**を、iPhone 14 の Safari で動く 3D シーンとして再現する。戦闘は第2段階で扱う。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 第1段階のゴール | 画像の雰囲気の再現（戦闘なし） |
| 対象端末 | iPhone 14（無印）の Safari、横向き |
| 技術 | 既存の Vite ＋ three.js。既存の移動テスト（`src/main.js`）を土台にする |
| 作り方 | 手前は3D、遠景の山と空は背景画像（案A） |
| 結晶獣 | AI生成（Artlist の Hyper3D Rodin v2.5 Fast、image-to-3D、無料枠1回） |
| その他の素材 | CC0 の無料ローポリ素材（Quaternius、Kenney など）とコード |
| 予算 | 0円 |

## 3. 対象外（第1段階では作らないもの）

- 攻撃・回避・ロックオンの動作、ボスの行動、ダメージ、勝敗
- HP・スタミナの増減、クエストの進行
- 滝、舞う葉
- 画像上部の「ビジュアル案｜未実装」の表示（企画用の注記のため）
- App Store／Google Play 向けのネイティブアプリ化

## 4. シーンの構成

### 配置
- **主人公**：手前の中央。カメラは背後から追う（既存の追従カメラとドラッグ操作を維持）。開始時は結晶獣とアーチが正面に見える向き
- **結晶獣**：奥の中央、崩れた石のアーチ2つの手前。高さは主人公（約1.8m）の2.5〜3倍（約4.5〜5.5m）
- **左右**：崖と岩壁で囲い、移動できる範囲の外枠にもする
- **地面**：色むらとゆるい起伏、石畳の道、草と小さな花の群れ
- **小物**：左手前に木の柱と青い旗2本、両脇に針葉樹
- **遠景**：山並みと夕焼けの空を、周囲を囲む背景画像で表示

### 素材の入手方法
| 対象 | 入手方法 | 補足 |
|---|---|---|
| 結晶獣 | AI（Hyper3D Rodin v2.5 Fast、無料枠1回） | コンセプト画像から獣の部分を切り出して入力する。Artlist へのアップロード直前にユーザーへ確認する |
| 結晶獣の動き | コード | 呼吸のような伸び縮み、結晶の発光の明滅 |
| 主人公 | CC0 の人型キャラクター素材 | 待機と走りのアニメーション付きのものを選ぶ。マフラーなどを青系に色替えする |
| 木・岩・草 | CC0 の自然素材 | |
| 廃墟のアーチ・旗 | コードで作る | 石ブロックを積み、欠けを入れる |
| 遠景の山と空 | AI（Artlist の無料の画像生成） | 人物や獣を含まない、パノラマの山並みと夕焼け |
| 顔アイコン | コンセプト画像から切り出す | |

### 失敗時の代わり
- **結晶獣**：生成に失敗した、見た目が使えない、または軽量化しても重すぎる場合は、岩の塊に発光する結晶を生やした獣をコードで組む。無料枠は1回なので作り直しはしない
- **遠景**：無料の画像生成が使えない場合（残り回数が3D生成と共通で足りない場合を含む）は、グラデーションの空とローポリの山のシルエットをコードで作る
- **素材のライセンス**：CC0 であることをダウンロード時に確認する。確認できない素材は使わない

## 5. 光・色・描画

- **太陽**：左奥の高い位置からの逆光。直射光はオレンジ寄りの暖色
- **環境光**：空側は青みの寒色、地面側は緑がかった茶色（HemisphereLight）
- **色調補正**：ACES Filmic のトーンマッピングと sRGB 出力
- **霧**：遠くほど青く霞ませ、3Dの地面と背景画像の境目をなじませる
- **ブルーム**：結晶獣の結晶（発光する青緑色）と空の明るい部分にだけ効かせる。半分の解像度で処理する
- **影**：太陽からの1方向のみ。影の範囲は主人公の周りに絞り、移動に合わせて追従させる。結晶獣も影を落とす
- **演出**：結晶獣の足元の土ぼこりと、空中を漂う光の粒（少量）
- **草**：GPU インスタンシングでまとめて描画し、頂点シェーダーで風に揺らす

## 6. 性能

### 目標
- iPhone 14 の画質「中」で 60fps。重い場面でも 30fps を下回らない

### 画質の3段階
| 項目 | 高 | 中 | 低 |
|---|---|---|---|
| 画面の解像度倍率の上限 | 2 | 1.5 | 1 |
| 草の量 | 多 | 中 | 少 |
| 影 | あり（細かい） | あり | なし |
| ブルーム | あり | あり | なし |

- 起動時は「中」で始め、最初の数秒の実測fpsが低ければ自動で一段下げる
- URL に `?q=high`、`?q=mid`、`?q=low` を付けると手動で固定でき、自動切り替えはしない
- 開発用の MacBook Air（2015、Intel HD Graphics 6000）は「低」で動く想定

### 素材の予算
- 結晶獣：三角形2〜3万枚程度まで削減する
- 画像：大きいもので最大2048px、主人公と小物は1024px
- 圧縮：gltf-transform（meshopt、画像は WebP）
- ダウンロード量：全体で15MB以内

## 7. UI

3D描画とは別に、HTML と CSS で画面の上に重ねる。

### 見た目
- 半透明の濃紺グレーの板に、細い金色の縁取りをつける。角は斜めに切り落とす
- 英字（YUTO、OBLIVION ARENA など）は Cinzel を使う。OFL ライセンスで、woff2 ファイルをプロジェクトに同梱する
- 日本語はシステムフォント（iPhone ではヒラギノ）で表示する
- アイコンは SVG で描く

### 要素と動作
| 場所 | 要素 | 第1段階での動作 |
|---|---|---|
| 左上 | 顔アイコン、YUTO、HPバー（緑）、スタミナバー（黄） | 表示のみ（満タン） |
| 右上 | クエスト「結晶獣の討伐 0/1」 | 表示のみ |
| 右上 | 円形のミニマップ（北の表示、獣のマーク、自分の矢印） | 動作する（自分の位置と向き、獣の位置） |
| 左下 | アナログスティック | 動作する（今の十字ボタンと置き換え） |
| 左下 | 走る | 動作する |
| 右下 | 攻撃（大）、回避、ロック | 押したときの見た目だけ |
| 下中央 | OBLIVION ARENA のロゴ | 表示のみ |

- 今左上にある操作説明の枠は外す。PCのキー操作（WASD／矢印キー、Shift、ドラッグでカメラ操作）は残す
- **スティック**：歩く速さ（3 m/s）に、倒した量（0〜1）を掛けて移動する。「走る」を押している間は 6 m/s
- **画面の向き**：横向き専用。縦向きのときは「横向きにしてください」と表示する
- **安全領域**：`env(safe-area-inset-*)` に合わせて配置し、ノッチやホームバーと重ならないようにする
- **全画面での起動**：Webアプリのマニフェストと `apple-mobile-web-app-capable` を追加し、「ホーム画面に追加」から全画面で起動できるようにする

## 8. コードの構成

```
src/
  main.js            起動とゲームループ（各部品をつなぐだけ）
  quality.js         画質3段階の決定と、fpsを見た自動切り替え
  input.js           キーボード・スティック・ボタンを1つの入力状態にまとめる
  player.js          主人公の読み込み、待機／走りアニメ、移動
  camera.js          背後から追うカメラとドラッグ操作
  world/
    lighting.js      太陽、環境光、霧、色調補正
    terrain.js       地面、石畳、崖、当たり判定の一覧
    ruins.js         アーチと旗
    vegetation.js    木、岩、草（風揺れ）
    backdrop.js      遠景の背景画像
    beast.js         結晶獣の読み込み、呼吸と明滅、失敗時の代わりの獣
    effects.js       土ぼこり、光の粒
    post.js          ブルーム
  ui/
    hud.js, hud.css  HP、クエスト、ボタン類
    stick.js         アナログスティック
    minimap.js       ミニマップ
public/
  models/  textures/  fonts/  manifest.webmanifest
assets-src/          ダウンロードした元素材（軽量化する前）
ASSETS.md            素材ごとの入手元とライセンスの記録
```

- **当たり判定**：既存の「円と点の距離」による方式を維持する。岩・崖・アーチの柱・結晶獣を円の一覧として `terrain.js` から提供し、`player.js` がそれを使う
- **入力**：`input.js` が `{ moveX, moveZ, run }` の形で毎フレームの入力を返す。キーボード、スティック、ボタンの違いはここで吸収する
- **素材の軽量化**：`npm run optimize` で `assets-src/` から `public/models/` と `public/textures/` に書き出す

## 9. 確認方法

### 自動テスト（Vitest）
- スティックの傾きから移動量への変換
- 当たり判定
- 画質の決定と、fpsによる自動での段階下げ
- ミニマップの座標変換

### 実機確認
- `vite --host` で起動し、同じ Wi-Fi の iPhone 14 で開く
- 開始直後の画面をコンセプト画像と並べて比べる

### 性能の計測
- `?debug` を付けると画面にfpsを表示する
- `npm run build` の出力で、ダウンロード量の合計を確認する

## 10. 完成条件

1. iPhone 14 の Safari を横向きにして開くと、開始直後の画面がコンセプト画像と同じ構図と雰囲気になっている
2. スティックと「走る」ボタンで歩き回れ、岩・崖・アーチ・結晶獣をすり抜けない
3. 画質「中」で 60fps、重い場面でも 30fps を下回らない
4. UI が画像どおりの配置で表示され、ミニマップが動く
5. ダウンロード量が合計15MB以内で、すべての素材の入手元とライセンスが `ASSETS.md` に記録されている

## 11. リスク

| リスク | 対策 |
|---|---|
| AIで作った結晶獣の品質や重さが想定と違う | 失敗時の代わりとして、コードで組む獣を用意する（4章） |
| Artlist の無料枠の残り回数の表示が一致しない（画像生成は2回、全体では1回と表示された） | 結晶獣の生成を優先する。遠景には代わりの方法を用意する（4章） |
| 開発用の Mac が遅く、見た目の確認がしにくい | 画質「低」で作業し、最終確認は iPhone 14 で行う |
| iPhone の Safari でのメモリ不足 | 画像の大きさの上限とダウンロード量の予算を守る（6章） |
